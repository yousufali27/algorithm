How it Works

        

          We place queens row by row. For each row, we try every column:
        

        
    
          
  • trying — column under test (yellow)
    • 
          
  • safe / under attack — conflict check
    • 
          
  • Place queen → recurse on next row
    • 
          
  • Backtrack if no valid column exists in a row
    • 
        

        

          Time complexity: O(N!) worst case
          · Space: O(N) for the recursion stack.

Problem 1: Count Solutions using Bitmasks

          
Rewrite the solver to use three bitmasks (columns, diag1, diag2) instead of arrays. What is the new time complexity?

          

            
            
          

          

            
Hint

            
Use (cols | d1 | d2) to get all attacked positions at once. Use the bit trick p = ~ (cols | d1 | d2) & ((1 << N) - 1) to find the rightmost available position. Each recursive step is now O(1) per candidate instead of O(N).

            
Solution Sketch

            
void solve(int row, int cols, int d1, int d2) {
    if (row == N) { ++solutions; return; }
    int avail = ~(cols | d1 | d2) & ((1 << N) - 1);
    while (avail) {
        int p = avail & -avail;     // rightmost bit
        avail -= p;
        solve(row+1, cols|p, (d1|p)<<1, (d2|p)>>1);
    }
}

            
Complexity becomes roughly O(N!) but with a much smaller constant — fast enough to count N=14 solutions in milliseconds.

Problem 2: Print Only the First Solution

          
Modify the backtracking code so it stops immediately after finding the very first valid arrangement.

          

            
            
          

          

            
Hint

            
You can throw an exception to unwind all recursive calls at once — or use a global bool found flag checked at the top of solve().

            
Solution Sketch

            
bool found = false;
void solve(int row) {
    if (found) return;
    if (row == N) {
        found = true;
        printBoard(board);
        return;
    }
    for (int c = 0; c < N; c++)
        if (isSafe(row, c)) {
            place(row, c);
            solve(row + 1);
            if (found) return;
            unplace(row, c);
        }
}

            
For a cleaner alternative, wrap the call in try { solve(0); } catch (SolutionFound&) {} where the base case throws.

Problem 3: No Three Queens Collinear

          
A variation: place N queens so that no three are collinear. Why does N=2 have no solution? For what N is it possible?

          

            
            
          

          

            
Hint

            
The standard N-Queens already forbids queens attacking each other, but two queens are still collinear with a third empty square. For N=2, every pair of squares is the same line, so we cannot avoid collinearity. A known result: solutions exist for all N ≥ 4 except a few small cases (see OEIS A000170).

            
Geometric Insight

            
Place queens on the boundary and one in the center. For N=5, try row positions {0,1,3,4,0} mapped to columns. The "no three collinear" constraint is strictly stronger than the classical constraint and requires a separate constructive proof.

EasyStability

          
Problem 1: Stable Sort for Duplicates

          
Among Bubble / Quick / Merge — which ones are stable (preserve the relative order of equal elements)? Why?

          

            
            
          

          

            
Hint

            
Bubble Sort's if (a[j] > a[j+1]) uses strict >, so it swaps only when strictly greater — equal elements keep their order. Quick Sort's partition uses < for the pivot, but it swaps across the boundary in arbitrary order — not stable.

            
Answer

            
Stable: Bubble Sort, Merge Sort. Unstable: Quick Sort (can be made stable with extra memory, but not by default).

          

        


        

          
MediumWorst-case

          
Problem 2: Quick Sort's Worst Case

          
Describe an input that triggers Quick Sort's O(n²) worst case. How do we fix it?

          

            
            
          

          

            
Hint

            
What happens when the array is already sorted and we always pick the rightmost element as pivot?

            
Answer

            
A sorted (or reverse-sorted) array with the rightmost pivot gives one partition of size 0 and one of size n-1 every level → O(n²). Fixes: random pivot, median-of-three, or switch to Heap Sort for small subarrays (Introsort).

Practice Problems


        

          
EasyBFS

          
Problem 1: Shortest Path in Unweighted Graph

          
Why does BFS give the shortest path (in edges) but DFS does not?

          

            
            
          

          

            
Hint

            
Think about the order in which nodes are visited. BFS uses a queue (FIFO), DFS uses a stack (LIFO).

            
Answer

            
BFS explores in concentric layers from the source — the first time we visit a node, we used the minimum number of edges. DFS dives deep and backtracks, so the first visit may use a long detour.

          

        


        

          
MediumDijkstra

          
Problem 2: Why Dijkstra Fails with Negative Weights

          
Dijkstra assumes non-negative edge weights. What goes wrong if there is a negative edge?

          

            
            
          

          

            
Hint

            
Once Dijkstra marks a node "settled", it never reconsiders it. Could a later path become shorter?

            
Answer

            
Yes — a path that goes through a negative edge after settling a node can produce a shorter total. Use the Bellman-Ford algorithm instead, which handles negative edges (and detects negative cycles) in O(VE).

EasyKnapsack

          
Problem 1: Subset Sum

          
Given numbers and a target T, decide whether some subset sums to T. How is this a special case of 0/1 Knapsack?

          

            
            
          

          

            
Hint

            
Set value = weight = a[i], capacity = T. Look only at dp[n][T] > 0.

            
Answer

            
If we set value[i] = weight[i] in the knapsack DP, then dp[n][T] > 0 iff some subset has total weight exactly T. We can also drop values entirely and use a boolean DP table.

          

        


        

          
MediumEdit Distance

          
Problem 2: Edit Distance (Levenshtein)

          
Modify the LCS recurrence to compute the minimum number of insertions/deletions/replacements to convert string A into B.

          

            
            
          

          

            
Hint

            
If a[i-1] == b[j-1], no operation is needed. Otherwise, take 1 + min(insert, delete, replace).

            
Answer

            
for (int i = 1; i <= m; i++)
  for (int j = 1; j <= n; j++)
    if (a[i-1] == b[j-1])
      dp[i][j] = dp[i-1][j-1];
    else
      dp[i][j] = 1 + min({dp[i-1][j],    // delete
                          dp[i][j-1],    // insert
                          dp[i-1][j-1]}); // replace

            
Complexity: O(m·n) time and space.

EasyFormula

          
Problem 1: Moves for N = 10

          
Without running the program, how many moves does it take to solve Tower of Hanoi with N = 10 disks?

          

            
            
          

          

            
Hint

            
Apply the recurrence T(N) = 2·T(N−1) + 1 with T(1) = 1. Closed form: T(N) = 2ⁿ − 1.

            
Answer

            
1,023 moves. Even at one move per second, that's ~17 minutes. N = 20 = 1,048,575 moves ≈ 12 days. N = 64 (legend) ≈ 585 billion years.

          

        


        

          
Medium4-Peg Variant

          
Problem 2: Reve's Puzzle (4 Pegs)

          
What if you have 4 pegs instead of 3? This is the Frame–Stewart problem — find a better algorithm.

          

            
            
          

          

            
Hint

            
Move the top k disks to a spare peg using all 4 pegs, then move the remaining N−k disks with 3 pegs, then move the k disks on top of them with 4 pegs.

            
Answer

            
Frame–Stewart: choose k ≈ N − √(2N+1) + 1. Best known formula grows like O(2^√N) instead of O(2^N). Exact optimum is still an open problem for arbitrary N.
